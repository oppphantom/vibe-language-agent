# 歌曲语境学习 Agent 设计

日期：2026-11-03

## 1. 目标

在不破坏现有本机网页、歌词检索和播放器桥接的前提下，把当前的“单选题演示”扩展为一条有证据、能补教、可判断是否达到学习目标的歌曲语境学习路径。

第一版需要做到：

1. 从已核验的教学材料生成固定但有前置关系的课程地图。
2. 覆盖听辨、含义、剧情、文化、休息和最终挑战六种节点。
3. 每次选择答案都由服务端评分，标准答案不下发浏览器。
4. 答错后在同节点给出针对性补教，允许重试；正确后只推进一次。
5. 重复提交保持幂等，旧节点和已完成会话的非法提交有明确错误。
6. 根据每轮真实作答记录更新表达掌握状态和薄弱环节。
7. 未配置模型时完整可用；配置模型后只增强解释，不接管评分。

## 2. 非目标

以下能力不在本次实现中，接口和文档也不得把它们描述为已经可用：

- 根据任意商业歌词自动生成并保证语义正确的完整课程。
- 未经人工核对的词形、文化背景或语气判断。
- 逐词时间戳、发音评分、录音上传和语音对话。
- 服务重启后的学习进度持久化。
- 让模型直接决定正确选项或接收浏览器提供的答案键。

真实歌曲接入的后续步骤是：先由媒体层提供带版本、来源和核对状态的歌词，再由教学内容层为可识别的目标表达提供经过审查的课程包。本次 Agent 内核使用同一结构运行，不绕过内容审查。

## 3. 现状与约束

当前 `backend/agent/session.js` 只有一个固定节点，能完成随机 ID 会话、答错补教、正确完成和提交幂等；`backend/agent/model.js` 只负责可选的单次解释。`shared/contract.js` 校验歌词和答案，`docs/API_CONTRACT.md` 规定正确答案留在服务端。

本次设计继续遵守以下仓库约束：

- 只用 Node.js 内置模块，不增加运行依赖。
- 浏览器交互与教学状态分离；本次只实现 Agent 和 API，不重做前端视觉。
- 原创固定样例继续明确标注来源，不能冒充“实时 Agent 生成”或人工核验的真实歌词。
- 浏览器只得到当前可答题面、选项、证据和地图状态，不得到正确索引、评分规则或内部补教条件。
- 内部字段沿用现有 JavaScript 项目的 `camelCase` 风格；HTTP 接口继续使用简短、语义稳定的资源名。

## 4. 方案比较

### 方案 A：纯模型实时规划

每次开始学习时把歌词交给模型，由模型即时生成节点、答案和补教。

优点是形式上最“智能”，能快速覆盖任意材料。缺点是缺少密钥时不可用、结果不可重复、模型可能编造文化依据，而且如果答案生成和评分都由模型完成，很难证明同一轮评价一致。该方案不适合作为当前本机离线产品的主链路。

### 方案 B：纯规则静态题目

继续使用固定单选题，只增加几个写死的页面节点。

优点是实现简单、结果稳定。缺点是并没有形成 Agent：没有材料充分性判断、证据链、自适应决策或可复用的课程结构，后续接真实歌曲时仍需重写。

### 方案 C：确定性教学内核 + 可选模型增强（采用）

课程由带来源和证据 ID 的课程包描述，Agent 负责分析材料、组织节点、维护学习状态、评分和决定下一步。模型只在配置后生成解释文本，并明确标记未人工核对。

该方案离线可测、服务端可审计，同时保留未来接入更丰富规划器的边界。确定性不代表不智能：本版会根据尝试次数、错误类型和提示使用情况更新掌握状态，并让补教与最终反馈使用这些证据。

## 5. 总体架构

```text
HTTP API
   │
   ▼
session.js ── 会话状态、幂等、节点推进、对外视图
   │
   ├── curriculum.js ── 材料检查、课程结构校验、公开题面/地图
   └── evaluation.js ── 服务端评分、补教反馈、掌握状态
           │
           └── content/fixtures/demo.js ── 原创材料与课程包

model.js ── 可选的解释增强，不参与会话推进和标准答案判定
```

### 5.1 `curriculum.js`

只负责与“教什么、为什么可教、浏览器能看什么”有关的规则：

- 从课程包索引找到歌曲对应的课程。
- 检查证据行是否存在、是否属于允许的歌曲、起止时间是否有效。
- 检查节点 ID 唯一、前置节点存在、选项和正确答案结构有效。
- 生成不包含答案键的当前节点、课程地图和材料投影。

该模块不保存会话，不记录提交。

### 5.2 `evaluation.js`

只负责一次答题的判断：

- 比较服务端选项与提交选项。
- 根据节点类型和答题历史生成错误类型与补教动作。
- 计算新的技能掌握摘要。
- 生成本次实际执行的工具日志。

该模块不直接修改会话存储，也不生成 HTTP 响应。

### 5.3 `session.js`

负责会话生命周期和所有状态变迁：

- 创建会话并保存当前节点位置。
- 校验会话、当前节点和提交 ID。
- 对同一提交 ID 返回第一次结果。
- 推进节点、记录历史并生成会话视图。

标准答案只存在于服务端课程对象中，公开节点不得包含 `correctIndex`、`remedial` 或内部变体。

### 5.4 `model.js`

保留现有 `POST /api/agent/explain`。模型输出继续受长度、字段和 HTTPS 端点校验。解释结果标明“AI 生成，未人工核对”，不进入评分链路。

## 6. 课程模型

课程包是一组原创、可审查的数据：

```text
Course
  id, title, language, targetExpression, songIds
  nodes[]

Node
  id, type, stage, skill, title, target
  prompt, options, correctIndex
  explanation, remedial, evidenceLineIds
  prerequisiteNodeId, provenance
```

节点类型固定为：

| 类型 | 阶段 | 学习目的 |
| --- | --- | --- |
| `listening` | 听辨 | 定位声音、重复或句内结构，不伪造逐词音频能力 |
| `meaning` | 含义 | 从上下文理解目标表达 |
| `story` | 剧情 | 在人物情境中选择贴切回应 |
| `culture` | 文化 | 区分歌词支持的有限解释与过度概括 |
| `rest` | 休息 | 用一句比较题复习本轮证据 |
| `challenge` | 最终挑战 | 在未展示过的新句子中迁移目标表达 |

每个节点必须引用至少一条材料证据。课程地图只公开节点标题、类型、状态、证据数量和来源标签，不公开题面中的正确答案。

## 7. 会话状态机

会话状态：

- `active`：存在可作答的当前节点。
- `completed`：所有节点已完成，不再接受新答案。

节点状态：

- `locked`：尚未到达。
- `active`：当前可作答。
- `completed`：已正确完成。

提交事件：

| 当前状态 | 事件 | 结果 |
| --- | --- | --- |
| `active` | 已见过的 `submissionId` | 原样返回第一次结果，不写历史 |
| `active` | 提交非当前节点 | `STALE_NODE`，不写历史 |
| `active` | 当前节点答错 | 保持 `active`，记录一次错误，返回 `remediate` |
| `active` | 当前节点答对且仍有下一节点 | 标记当前节点完成，推进到下一节点 |
| `active` | 最终节点答对 | 会话变为 `completed` |
| `completed` | 新提交 | `ALREADY_COMPLETED`，不写历史 |

客户端提交的 `attempt` 只作为展示信息保留；评分和掌握判断使用服务端该节点已有的历史次数，避免客户端伪造“第一次就答对”。

## 8. 自适应规则

每个技能维护：

```text
attempts, errors, hintsUsed, status
```

状态按以下规则确定：

- `new`：尚未提交。
- `needs_review`：同一技能出现错误，或答对时使用过提示。
- `practicing`：已无错误但尚未完成迁移节点。
- `mastered`：最终挑战正确，且该技能在最终节点没有再次暴露错误。

补教动作根据节点类型使用不同错误标签：

| 节点 | 错误标签 | 补教重点 |
| --- | --- | --- |
| 听辨 | `listening_gap` | 回看歌词位置与重复结构 |
| 含义 | `context_misread` | 对比前后句事件 |
| 剧情 | `usage_gap` | 检查回应是否保持人物关系和时态 |
| 文化 | `context_overgeneralization` | 收回无法由材料支持的宏大结论 |
| 休息 | `review_gap` | 重新指出两条证据的连接 |
| 挑战 | `transfer_gap` | 分开理解目标表达和新句子的语境 |

反馈会附带本轮薄弱技能摘要和学习者可见的下一步。公开摘要只描述已发生的作答行为，不展示模型隐藏推理。

## 9. API 兼容策略

保持现有入口：

- `POST /api/sessions`
- `GET /api/sessions/{id}`
- `GET /api/sessions/{id}/node`
- `POST /api/answers`

为兼容旧前端，当前节点仍返回 `id`、`type`、`target`、`prompt`、`options`、`material`、`status` 和 `provenance`。新增：

- `title`：节点标题。
- `stage`：阶段名称。
- `evidence`：当前节点引用的最小歌词证据。
- `map`：只含公开信息的课程地图。
- `progress.current`：当前或已完成节点数。

会话视图新增：

- `status`：`active` 或 `completed`。
- `mastery`：目标表达、技能状态和薄弱技能摘要。
- `startedAt`、`updatedAt`：本轮内存会话时间。

旧字段 `mode`、`schemaVersion`、`currentNodeId`、`route`、`history`、`progress.completed`、`progress.total` 和 `songId` 保留。

## 10. 错误处理

沿用现有 `error.code` 到 HTTP 状态码的映射，并增加：

- `STALE_NODE` → 409：浏览器仍停留在旧节点。
- `INVALID_INPUT` → 400：参数、选项或提交结构无效。
- `NOT_FOUND` → 404：歌曲、课程、会话或节点不存在。
- `ALREADY_COMPLETED` → 409：已完成会话再次提交。
- `COURSE_INVALID` → 500：服务端课程包结构不合法，属于配置错误。

错误消息使用中文并保持可操作。业务代码不把内部异常原文、密钥或模型请求内容返回浏览器。

## 11. 测试策略

使用 Node.js 内置测试，不访问真实音乐软件或模型：

1. 课程包校验：证据存在、节点 ID 唯一、每节点答案合法、公开题面不泄题。
2. 材料充分性：缺目标表达或缺证据时不生成课程。
3. 全流程：六类节点按顺序完成，进度从 0 到 6。
4. 补教：每个阶段首次答错停留当前节点、不增加完成数、产生特定错误类型。
5. 幂等：同一提交重复发送返回同一对象，历史只增加一次。
6. 非法提交：非当前节点、已完成会话、越界选项各有明确错误码。
7. 自适应：错误和提示使用会改变服务端技能状态与薄弱点，客户端尝试次数不能伪造掌握。
8. HTTP smoke：完整走通创建、地图、六节点、最终完成和重复查询。
9. 现有歌词、播放器和契约测试全部继续通过。

## 12. 验收标准

- `npm run check` 与 `npm run smoke` 全部通过。
- 未配置任何模型密钥时，可以从 `POST /api/sessions` 走到 `completed`。
- 任一节点的公开响应中不存在正确答案字段。
- 同一 `submissionId` 不会重复增加历史或进度。
- 答错不会跳过节点，答对只推进一个节点。
- 最终会话能给出六类阶段进度、已掌握/待复习状态和本轮错误摘要。
- 原有 API 字段继续可供当前前端读取。
