# 歌曲定制 ASCII 地下城设计

日期：2026-11-03

依据：`CONTENT_PATH_REQUIREMENTS.md`

## 1. 目标

每首歌拥有一套由专用 Agent 设计的可玩地下城。Agent 根据歌曲主题、歌词密度、重复表达和知识节点决定普通关卡数量、每关布局和实体组合；系统固定追加一关“串词成句”。

核心玩法：

```text
WASD/方向键移动 @
  → ♪ 自动播放歌词，弹窗进行三句听音辨词
  → ? 碰到 NPC，回答语境/词义/情感题
  → ✦ 获得包含读音、意思、用法、例句的知识卡
  → 离开当前层
  → 最终关循环播放目标歌词
  → 按顺序踩中散落的单字
  → 完整还原歌词后通关
```

## 2. 方案选择

### 纯模板

关卡数与地图固定，稳定但无法体现歌曲特征，不采用。

### 模型直接画完整字符图

模型直接输出 19×9 墙体和坐标。自由度高，但容易生成死路、重叠实体或不可达出口。

### 专用 Agent + 安全地图工具（采用）

模型决定关卡数、主题、布局类型和实体内容；工具把实体填入经过验证的可行走格，出口固定可达。地图内容仍由 Agent 决定，结构错误由工具消除。

## 3. 专用 Agent

`backend/agent/dungeon-agent.js`：

1. 输入歌曲、目标表达、歌词行和已校验知识节点。
2. 决定 2–5 个普通关卡。
3. 每关从 `gallery`、`crossroads`、`garden`、`spiral`、`ambush` 中选择布局。
4. 每关选择人格，并组合 3–8 个 `note`、`npc`、`card` 实体；每关至少两个音符/NPC事件和一张知识卡。
5. 固定生成最终单字散布关，并由 Agent 提供 `scatterSeed`。
6. 服务端校验失败时允许一次模型修复；再次失败则拒绝课程。

工具职责：

- `validateDungeon`：检查关卡数、实体、歌词引用、选项、正确答案、知识卡字段、终局歌词行和散布种子。
- `createRoom`：根据布局和实体数量把对象放入安全格子。
- `roomView`：生成玩家看到的 ASCII 网格和图例。
- `moveRoom`：墙体、碰撞、对象触发和出口判定。
- `respondRoom`：题目答题、正确推进、错误补教。

## 4. 实体契约

### 音符

```text
kind: note
lineId: 实际歌词行
prompt: 听音辨词题面
options: 3 句完整歌词
correctIndex: 服务端保存
explanation: 播放歌词与辨析依据
```

碰到 `♪` 时前端自动调用现有播放器播放该行，并弹出三项歌词。答对后音符消失，答错保留并显示解释。

音符播放失败时使用可取消的指数退避重试：

- 第一次立即播放；失败后等待约 350ms、700ms、1.4s……最长 4s 再试。
- 只在当前音符题仍打开、尚未答对、仍在学习页时继续。
- 任意一次请求成功后停止重试。
- 答对、关闭题目、切换关卡、离开学习页时立即取消。
- Windows 播放桥内部按句串行执行，避免旧请求的句末暂停静音新请求。

### NPC

```text
kind: npc
lineId: 证据行
prompt: 情境、词义、情感或文化问题
options: 3 项
correctIndex: 服务端保存
explanation: 补教
```

NPC 必须真正覆盖歌词知识，不能只问与歌词无关的泛知识。

### 知识卡

```text
kind: card
card:
  term, reading, meaning, usage, example, lineId
```

碰到 `✦` 后立即收入行囊并弹出卡片；无需答题。

## 5. 最后一关：串词成句

- 系统固定追加，Agent 不能省略。
- Agent 选择一条去除空格后包含 2–24 个字符的高频歌词。
- 服务端逐字拆分，忽略空格但保留标点；单字必须按顺序还原该歌词。
- 地图直接显示每个原始单字，不使用数字编号；右侧不公布完整正确顺序。
- Agent 提供 `scatterSeed`，地图工具据此打乱所有可用格，不能按歌词顺序平铺。
- 进入关卡后自动循环播放目标歌词句；离开或完成后停止循环。
- 踩错单字会清空进度，从第一个字重新开始。
- 全部单字顺序正确后出口 `>` 打开。

## 6. 运行时状态

```text
room
  player, enemies, walls, objects
  resolved[]
  pending: {objectId, challenge}
  charProgress
  turn
```

移动和答题分别通过：

- `POST /api/moves`
- `POST /api/respond`

两者都支持 `submissionId` 幂等。存在未回答弹窗时，移动接口返回 `pending`，玩家必须先完成题目或关闭弹窗后选择答案。

## 7. 前端

- 顶部展示 Agent 决定的关卡路线、经验和行囊。
- 中央为 CRT 风格 19×9 ASCII 地图。
- 键盘 WASD、方向键与触屏方向键控制角色。
- 音符/NPC 使用弹窗答题；答错保留当前挑战。
- 知识卡以收藏卡弹窗展示。
- 侧面只显示任务、对象进度和最近探索记录；最终关不提供明显词序答案。
- 最终关直接在地图上叠加真实单字，并只在踩对后显示已接上的前缀。
- 全部通关后显示“重新生成知识关卡”和“返回音乐界面”两个选择。
- 重新开始会创建全新会话；AI 课程重新调用地下城 Agent，旧进度不会沿用。
- 选择重新生成后，关闭按钮、选项、遮罩、键盘和背景交互全部锁定，直到请求成功或失败；服务端同时合并重复重开请求。

## 8. 错误与安全

- 标准答案、解释和知识卡内容不放在地图公开格中。
- 题目只有碰撞后才下发选项，且仍不包含 `correctIndex`。
- 未知歌词行、缺少散布种子、缺少三类实体或关卡数越界都拒绝课程。
- 已完成/旧房间请求返回明确错误。
- AI 课程仍标注「AI 生成，未人工核对」。

## 9. 测试

1. Agent 生成 2–5 个普通关，并固定追加最终关。
2. 缺少 note/npc/card 任一类时校验失败。
3. 音符正确选项必须等于实际播放歌词。
4. 碰到 NPC 和音符后移动暂停，答对后恢复。
5. 知识卡包含五类知识字段。
6. 最终单字可还原原歌词，顺序错误重置，位置由种子打乱而非按行平铺。
7. 噪声碰撞只退一步，保留已收集知识。
8. `/api/moves`、`/api/respond` 幂等。
9. HTTP smoke 用 WASD 和弹窗答题完成三语与 AI 地下城。
10. 真实模型完成一次地下城生成。
11. 每关至少三个实体，避免单对象空房间。
12. Windows 连续逐句播放严格串行，旧句末暂停不能静音下一音符。

## 10. 验收标准

- 不同歌曲可以生成不同关卡数量和地图内容。
- 用户必须实际操控角色探索地图。
- 音符会触发歌词片段播放和三句听辨题。
- NPC 会触发歌词相关知识题。
- 知识卡会展示读音、意思、用法和例句。
- 固定最终关按单字顺序完成。
- `npm run check`、`npm run smoke`、`npm run smoke:model` 全部通过。
