# 韩中日多语言 Agent 扩展设计

日期：2026-11-03

## 1. 目标

让现有歌曲语境学习 Agent 同时支持三种学习目标语言：

- 韩语：`ko`
- 日语：`ja`
- 中文：`zh`

网页操作界面继续使用中文。多语言是指学习者正在学习的歌词与课程语言，不是让整个 UI 自动切换成目标语言。

本次需要覆盖：

1. 三种语言各有一套原创、可离线完成的六阶段课程。
2. 课程、歌曲、会话和模型解释都携带明确的语言代码。
3. `/api/songs` 返回统一语言注册表，浏览器不再写死“韩语”。
4. LRCLIB、网易云和 QQ 音乐歌词检索接受 `language`，旧请求缺省为 `ko`。
5. 模型解释根据所选语言生成对应教学提示词。
6. 前端提供学习语言选择，并正确显示三语歌词文本。
7. 不支持的代码、课程语言与歌曲语言不一致时失败关闭。

## 2. 非目标

- 自动检测一首歌的语言。语言由用户明确选择，搜索到的歌词语言标记为“用户选择，未自动核验”。
- 把网页 UI 翻译成韩语或日语。
- 生成逐句翻译、发音评分或语音识别。
- 根据任意商业歌曲自动生成并核验新课程。

## 3. 方案选择

### 方案 A：按语言复制三套 Agent

分别维护韩语、日语、中文的会话与评分模块。

实现直观，但状态机、幂等、补教和测试会重复三份，任何修复都要改三次，违反现有职责边界。

### 方案 B：只增加多语言演示数据

保留韩语流程，另外写几张日语和中文静态卡。

改动较少，但歌词检索和模型提示词仍会标成韩语，不能称为系统支持三种语言。

### 方案 C：统一语言注册表与共享课程内核（采用）

一个语言注册表约束语言代码和展示名称；课程包声明自己的语言；现有 `curriculum.js`、`session.js`、`evaluation.js` 继续处理所有语言。媒体与模型适配器只消费规范化后的语言代码。

该方案复用现有状态机和测试结构，同时把语言差异集中在可验证的边界。

## 4. 架构

```text
shared/languages.js
  ├── 语言代码、中文标签、本地名称
  └── 规范化与拒绝未知语言
          │
          ├── shared/contract.js
          ├── backend/agent/curriculum.js
          ├── backend/agent/session.js
          ├── backend/media/*-lyrics.js
          └── backend/agent/model.js

content/fixtures/demo.js
  └── 韩语、日语、中文三套原创课程

HTTP API
  └── /api/songs 返回 languages + 带 languageLabel 的歌曲
```

`curriculum.js` 继续负责证据、节点和公开题面校验；多语言不会新增一套状态机。

## 5. 数据契约

语言对象：

```text
Language
  code: 'ko' | 'ja' | 'zh'
  label: '韩语' | '日语' | '中文'
  nativeLabel: '한국어' | '日本語' | '中文'
```

课程新增或强化：

```text
Course
  language: Language.code
  languageLabel: 由注册表派生，不手写重复事实
```

会话新增：

- `language`
- `languageLabel`

公开节点新增：

- `language`
- `languageLabel`

歌曲仍使用 `language`，公开投影可增加 `languageLabel`。歌词行本身不必重复语言代码，因为每行已经通过 `songId` 归属歌曲。

## 6. API 兼容

- `POST /api/lyrics/search` 新增可选 `language`。缺省为 `ko`。
- `POST /api/agent/explain` 新增可选 `language`。缺省为 `ko`。
- `GET /api/songs` 新增 `languages` 数组；歌曲增加 `languageLabel`。
- 旧客户端不传语言时行为保持韩语。
- 传 `ko`、`ja`、`zh` 以外的代码返回 `400 INVALID_INPUT`。

语言是用户选择的元数据，不是从歌词内容检测出的结论。外部歌词仍保留原有来源和未人工核对状态。

## 7. 课程与显示规则

- 每个课程必须关联同语言歌曲，所有证据行必须来自这些歌曲。
- 三语课程共用 `listening`、`meaning`、`story`、`culture`、`rest`、`challenge` 六类节点。
- 目标表达按普通 Unicode 字符串匹配；中日文本不做 IPA 或词形推断。
- 前端语言选择决定演示筛选、真实歌词检索语言和模型解释语言。
- 歌词展示使用通用 CJK 字体栈，并附加 `language-ko`、`language-ja` 或 `language-zh` 类，便于后续按语言调整排版。

## 8. 错误与降级

- 未知语言：`INVALID_INPUT`。
- 课程语言与关联歌曲不一致：`COURSE_INVALID`，服务端课程配置错误。
- 模型未配置或失败：原有离线课程仍可用，解释功能返回既有错误。
- 歌词来源失败：保留原错误；不伪造其他语言歌词。

## 9. 测试

1. 语言注册表接受 `ko`、`ja`、`zh`，拒绝未知代码。
2. 三套课程均通过证据、节点顺序、答案索引和语言一致性校验。
3. 三种语言都能从创建会话走到六阶段完成。
4. 混合课程语言与歌曲语言被拒绝。
5. 歌词适配器接收显式语言；旧的缺省调用仍返回韩语。
6. 模型请求把所选语言写入提示词。
7. HTTP smoke 覆盖三语歌曲目录和至少一轮日语、中文流程。
8. 原有韩语、播放器和媒体测试继续通过。

## 10. 验收标准

- `npm run check` 与 `npm run smoke` 全部通过。
- `/api/songs` 明确返回三种语言和六首原创样例。
- 选择日语或中文课程可以离线完成六阶段学习。
- 真实歌词检索与模型解释不再无条件标成韩语。
- 公开课程题面仍不包含标准答案。
- 旧韩语 API 调用无需修改即可继续工作。
