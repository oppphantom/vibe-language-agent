# 真实歌曲 AI 学习链路设计

日期：2026-11-03

## 1. 目标

把当前分离的“音乐播放”和“离线教学演示”连成一条真实用户路径：

```text
连接音乐软件
  → 匹配当前歌曲同步歌词
  → 用户点击开始学习
  → AI 分析所选歌词并生成六阶段课程
  → 服务端校验证据与答案结构
  → 创建学习会话
  → 在学习地图中答题、补教、回听证据并完成迁移挑战
```

模型配置从仓库根目录 `.env` 读取；`.env` 已被 Git 忽略，密钥不进入响应、日志、浏览器或仓库。

## 2. 非目标

- 不把任意商业歌曲的 AI 课程描述为人工核对内容。
- 不在本版加入开放式回答、语音识别或发音评分。
- 不持久化完整歌词、学习记录或动态课程；服务重启后内存会话失效。
- 不在课程生成失败时伪造备用答案或静默降级成不相干课程。

## 3. 方案选择

### 方案 A：AI 生成课程结构，服务端强校验（采用）

模型根据歌曲信息和受长度限制的同步歌词，生成一个目标表达和六个教学节点。服务端忽略模型提供的课程语言、课程 ID 和会话状态，自行补齐时间、来源、节点 ID、前置关系与公开投影，并使用现有课程校验器验证。

优点是能处理真实歌曲，状态机和评分保持确定性，模型输出错误可以失败关闭。缺点是需要可用模型，生成有等待时间和调用成本。

### 方案 B：只匹配人工课程包

真实歌曲必须提前有课程包才能学习。

可审计性最高，但无法满足当前“任意正在播放歌曲尽快进入学习”的目标，不能解决已连接歌曲没有课程的问题。

### 方案 C：浏览器直接生成题目

浏览器把歌词发给模型并自行保存答案。

实现快捷，但会暴露答案键、绕过统一契约，并把密钥与提示词带入浏览器，不符合现有信任边界。

## 4. 后端组件

### 4.1 `backend/env.js`

- 仅在直接启动 HTTP 服务时加载仓库根目录 `.env`。
- 优先使用 Node.js 内置 `process.loadEnvFile`。
- 不覆盖已经存在的进程环境变量。
- 不记录文件内容；文件不存在时继续使用静态课程。

### 4.2 `backend/agent/llm.js`

统一封装兼容 Chat Completions JSON 模式的模型调用：

- 校验 HTTPS 端点，拒绝本机、IP 直连和 URL 内凭据。
- 从环境变量读取端点、模型名和密钥。
- 使用服务端超时和 `redirect:"error"`。
- 只把响应内容解析为 JSON 对象，并统一 `MODEL_UNAVAILABLE`、`MODEL_UPSTREAM`、`MODEL_OUTPUT` 错误。

现有 `model.explain` 和新的课程规划器复用这一适配层。

### 4.3 `backend/agent/planner.js`

输入经过运行时校验的歌曲和歌词：

- 只使用有歌词文本的行，最多取前 60 行。
- 至少需要四行、连续时间信息不完整时仍可规划文本任务，但不宣称逐句音频可用。
- 要求模型选择在至少两行中出现的短表达。
- 要求模型生成固定顺序的六类节点：`listening`、`meaning`、`story`、`culture`、`rest`、`challenge`。
- 要求每节点三个选项、一个正确索引、答案说明、补教提示和证据行 ID。
- 服务端重写课程 ID、语言、来源、歌曲关联、节点 ID、阶段名称和前置关系。
- 使用现有 `validateCourse` 检查目标表达、证据归属、选项与答案索引。
- 生成失败时返回明确错误，不创建会话。

动态课程注册到内存课程仓库，TTL 为 2 小时；只保留投影所需的歌曲元信息与所选歌词行。过期清理由独立存储层负责，不把清理状态放进会话状态机。

## 5. 模型输出契约

模型只需要返回：

```json
{
  "targetExpression": "다시",
  "title": "다시：让未完成的事重新发生",
  "nodes": [
    {
      "type": "listening",
      "skill": "听辨定位",
      "title": "找到重复的落点",
      "prompt": "中文题面",
      "options": ["选项 A", "选项 B", "选项 C"],
      "correctIndex": 0,
      "explanation": "正确答案依据",
      "remedial": "答错后的补教提示",
      "evidenceLineIds": ["歌词行 ID"]
    }
  ]
}
```

服务端验证：

- `targetExpression` 长度为 1–40，且在材料里至少命中两行。
- 节点恰好六个且类型顺序正确。
- 每节点选项恰好三个，正确索引为 `0`、`1` 或 `2`。
- 证据行 ID 来自本次材料。
- 课程语言与所选语言一致。
- 公开节点和规划响应不包含 `correctIndex`、`remedial` 或答案说明。

## 6. API

### `POST /api/agent/plan`

请求：

```json
{
  "song": {
    "id": "实时歌词来源生成的歌曲 ID",
    "title": "歌名",
    "artist": "歌手",
    "language": "ko",
    "version": "版本",
    "durationMs": 180000,
    "source": {"kind": "lrclib", "id": 123}
  },
  "lines": [
    {
      "id": "歌曲 ID-1",
      "songId": "歌曲 ID",
      "text": "同步歌词",
      "startMs": 1000,
      "endMs": 4000,
      "source": {"kind": "lrclib", "id": 123},
      "reviewStatus": "unverified"
    }
  ],
  "language": "ko"
}
```

成功返回：

```json
{
  "courseId": "服务端课程 ID",
  "title": "课程标题",
  "targetExpression": "다시",
  "language": "ko",
  "languageLabel": "韩语",
  "nodeCount": 6,
  "provenance": "AI 生成，未人工核对"
}
```

### `POST /api/sessions`

兼容两种请求：

- 原创课程：`{"songId":"demo-morning"}`
- 动态真实歌曲课程：`{"courseId":"服务端课程 ID"}`

动态课程只能通过服务端课程仓库启动，浏览器不能提交节点、答案或来源快照。

## 7. 前端流程

1. 音乐页获得同步歌词后显示“生成歌曲学习地图”按钮。
2. 点击后提交当前歌曲、歌词和语言到 `/api/agent/plan`。
3. 成功后调用 `/api/sessions` 创建会话，切换到新的“学习地图”模式。
4. 学习地图沿用现有六阶段界面、答案提交、补教和进度恢复逻辑。
5. 每一条材料显示来源；动态课程显示“AI 生成，未人工核对”。
6. 学习页提供返回音乐页的入口，当前客户端播放的歌曲不因切换页面而被控制。
7. 模型未配置或生成失败时，保留歌词和播放能力，并显示可操作错误。

## 8. 测试

自动测试使用注入的假模型，不访问外部服务：

1. `.env` 加载器不覆盖已有环境变量。
2. 统一模型适配器拒绝不安全端点与空响应。
3. 规划器把真实歌词转成合法六阶段课程，并移除公开答案。
4. 模型返回缺节点、越界答案、伪造证据或不足两处目标表达时失败关闭。
5. 动态课程可以创建会话并完成全部六阶段。
6. 静态 `songId` 会话继续通过原有测试。
7. HTTP smoke 覆盖歌词材料 → 规划 → 动态会话 → 完成。
8. 使用 `.env` 配置的真实模型做一次最小原创材料联调；只记录成功/失败类型，不记录密钥、端点或完整歌词。

## 9. 验收标准

- 打开真实歌曲同步歌词后，可以直接生成并进入六阶段学习地图。
- 课程生成与学习会话都由服务端维护，浏览器不获得标准答案。
- 模型输出不合法时不会出现“看似可学但无法评分”的课程。
- 不配置模型时，原有原创三语课程继续可用。
- `npm run check` 与 `npm run smoke` 全部通过。
- `.env` 不在 Git 状态中，模型密钥不会出现在响应、错误或日志里。
